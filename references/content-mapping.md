# 内容映射：从原文到画面

不要从文章标题直接跳到生图 prompt。先建立一份小型语义地图，再选择值得画的认知锚点。

## 1. 找到作者真正的判断

对候选段落提取：

- 原句锚点：能代表本段判断的短句或准确段落位置。
- 表层主题：这段在谈什么。
- 核心判断：作者对这个主题说了什么。
- 关系：因果、对比、转化、顺序、分层、反馈、瓶颈、选择或状态变化。
- 内容词：原文中的关键名词、动词、结果词。
- 读者 takeaway：看完图应记住的一句话。

“AI”“成长”“产品”只是主题，不是判断。“AI 接管重复工作，让人保留判断与创造”才是可画的判断。

## 2. 选择认知锚点

优先选择：

- 文章的核心结论或反常识判断。
- 前后逻辑发生变化的转折。
- 有明确输入、动作和结果的机制。
- 读者容易混淆、但一张图能讲清的关系。
- 能用角色动作而不是装饰图标表达的段落。

跳过重复论述、纯背景事实和无法增加理解的段落。多图之间不要重复同一个判断。

## 3. 建立逐项对应

先用文章自己的名词和动词，再考虑外部隐喻：

| 原文元素 | 画面对应 |
|---|---|
| 主体或输入 | 可见对象、容器或材料 |
| 关键动作 | 角色亲手执行的物理动作 |
| 阻力或问题 | 卡住、堆积、泄漏、断裂、错位等状态 |
| 机制或路径 | 空间关系、连接、顺序或少量箭头 |
| 结果 | 明显改变后的对象或角色状态 |

每张图至少保留两个来自原文的可见对象和一个来自原文关系的动作。没有对应关系的装饰物应删除。

## 4. 再发明视觉隐喻

把关系改写为物理变化：

- 因果：触发器导致另一端发生变化。
- 对比：同一对象处于两种状态。
- 转化：材料经过角色操作后变成结果。
- 瓶颈：路径在一个关键位置堵塞或断裂。
- 反馈：输出沿另一条路径回到输入。
- 分层：角色搭建、穿越或维护不同层。

优先使用与文章领域有关的对象；只有抽象关系难以直接画时，才使用桥、机器、漏斗等通用物件。不要反复使用灯泡、齿轮、机器人、火箭或通用 UI 图标。

## 5. Shot list 格式

```text
图 01
放置位置：
原句锚点：
读者 takeaway：
关系 / 结构：
视觉隐喻：
角色动作：
姿态计划：角色实例数；身体朝向；左臂/左手；右臂/右手；遮挡；可见手数量；一个主要动作
内容对应：原文 A → 对象 A；原文 B → 对象 B；关系 C → 动作 C
中文文字计划："词1" → 对象/位置；"词2" → 关系/位置
画幅与留白：
```

## 内容贴合度自检

- 换成另一篇同主题文章后，这张图是否仍可原样使用？如果可以，说明过于泛化。
- 图中是否出现原文没有支持的新结论？如果有，删除。
- 视觉焦点是否对应作者最重要的判断，而不是最容易画的名词？
- 读者能否从动作和短词看懂“发生了什么变化”？
