# 构图与视觉隐喻

先完成 `content-mapping.md`，再选择结构。结构服务原文关系，不要先套模板再硬塞内容。

## 关系到结构

- Workflow：输入、处理、输出；适合明确步骤或转化。
- Before / After：同一对象的两个状态；适合变化和效果。
- Comparison：两个选择或策略；适合差异与取舍。
- System：3-5 个关联部件；适合协作、循环和机制。
- Journey / Map：弯曲路径与少量节点；适合成长、演进和阶段。
- Funnel：收集、筛选、收敛；只在原文真的强调筛选时使用。
- Layer：能力栈或层级；角色搭建、穿越或维护层级。
- Character State：2-4 个动作状态；适合心理与行为变化。
- Conceptual Metaphor：一个生活或低科技物件承载抽象关系。
- Mini Comic：2-4 格，每格一个动作，形成转折。
- Cause → Effect：清楚的触发与结果，角色执行或承受因果。

## 从关系到动作

1. 用一句“主体 + 动作 + 结果”写出原文判断。
2. 把抽象关系换成物理状态：堵塞、泄漏、堆积、分叉、变重、断裂、回流、压缩、穿透、组装。
3. 优先选择文章领域中的对象；不足时再选箱子、滑轮、门、秤、抽屉、线团、旧机器、筛子等隐喻物。
4. 让角色亲手改变关键状态：拉、推、搬、接、拆、装、分类、连接、记录、修补、观察、穿越。
5. 给输入、动作节点和结果各安排必要的中文短词。
6. 删除没有原文对应关系的对象、箭头和装饰。

## 动作容量与拆图

- 一张连续场景默认一个角色实例，一个主要动作。
- 另一只手最多承担一个自然的辅助动作；必须在姿态计划中明确左右手与接触对象。
- 需要三个以上独立动作时，不要让同一个身体硬做。拆成多张图、2-3 格 mini comic，或让机器输出和结果对象表达其余步骤。
- 错误示例：角色一只手投递资料、一只手比较卡片，同时又伸出第三只手搭积木。
- 正确示例：工作台自动吸入并处理资料；角色双手共同把一张已选方案卡插入创作台，让新结构出现。这样用一个协调动作同时表达“判断 → 创造”。若仍过载，再拆成两张或两格。
- 桌面、栏杆、大道具容易遮断手臂。若不能清楚说明肩膀到手的路径，改姿态或减少遮挡。

## 多图去重

为整组 shot list 记录：原文关系、结构、主物件、角色动作、阅读方向。连续两张不得四项都相同；同一物件不因换标签就算新隐喻。

## 避免 PPT 化与海报化

- 不用规整网格承载所有信息，不给每个节点加解释框。
- 不在画面写“流程图 / 架构图 / 对比图”等类型标题。
- 不用一个巨大标题替代内容表达。
- 箭头只表达必要关系；能用动作、遮挡或空间表达就不用箭头。
- 让一个记忆点统领画面，文字贴近对象和关系，不漂浮成列表。
